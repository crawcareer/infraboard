Help

The Summary page (this app's home page) has two panels:

  • My Tasks — every task currently assigned to you that isn't done yet. Each row shows the candidate it's for, the task itself, whether it's a Pre-Hire or Post-Hire task, and its due date. A row is highlighted yellow if it's due today, or red if it's overdue.
  • Candidates by Status — a count of candidates in each stage of the pipeline (Prospect, Interviewing, Offer, Hired, Offboarding, Rejected, Archived), with a link through to the full candidate list.

Adding a candidate

Candidates → Add candidate. Only the name is required; email, phone, position, status, and start date are all optional and can be filled in later. You can also attach a resume right away, or add one afterward from the candidate's own page.

Adding timeline events

Open a candidate and use "+ Add event" under the Pre-Hire or Post-Hire timeline to add a one-off task by hand. If you'd rather start from a checklist, set the candidate's status to "Hired" (or click "Generate timelines from templates") to fill in both timelines automatically from whichever Timeline Templates exist — due dates get calculated from the candidate's start date. Each task can be assigned to a team member, given a due date, and checked off once it's done.

Check Recurring (available when adding or editing a task) to have it repeat instead of staying done — useful for things like a license renewal. Set how often ("Recurs every ___ months/years", minimum 1 month) and give it a due date. Once that due date arrives, the task automatically gets a new due date that far out and reverts to pending, whether or not it was ever checked off — the same person stays assigned each time around.

Adding an automated email task

From a candidate's Pre-Hire or Post-Hire timeline, click "+ Add Automated Email" and choose an email type: Infradapt Onboarding, Rejection, Interview Request – Phone, Interview Request – In Person, or Offer. Pick the date it should go out, then click Preview to see the email the system will generate. You can edit the subject and body before creating the task — whatever you save is exactly what gets sent, automatically, on that date.

Infradapt Onboarding always goes to Infradapt's support address. The other four go to the candidate's own email address instead — so the candidate needs an email on file for those to be available. Every type Cc's you (as whoever created the task) as the point of contact for any replies.

Timeline Templates are reusable checklists that get copied onto a candidate's Pre-Hire, Post-Hire, or Offboarding timeline. There are two ways to have them:

  • Default templates — click "Generate default templates" here to create ready-made "Pre-Hire", "Post-Hire", and "Offboarding" checklists covering the usual steps (paperwork, equipment, IT accounts, training, check-ins, access revocation, and so on). It only creates whichever of the three don't already exist, so it's safe to click even if you already have some of them.
  • Custom templates — click "New template" to build your own from scratch, or open an existing one to add, reorder, or remove its events. Each event has a title, an optional description, and a day offset (how many days before or after the anchor date — a candidate's start date, or an offboarded employee's last day — it's due).

A template's name matters only for the three specifically named "Pre-Hire", "Post-Hire", and "Offboarding" — those are what get applied automatically (the first two when a candidate is hired, the third when you click Offboard on Team). Other templates you create are available from a candidate's page but aren't applied automatically.

Employee vs. Admin

Employee accounts can create and manage candidates, be assigned tasks, and create or edit Timeline Templates. They can also see this Team page, but only to open a team member's Edit page and check/uncheck which assets that person has — they can't change anyone's name, email, role, or active status, and can't add or remove team members. Admin accounts can do everything an Employee can, plus all of that, plus offboard people and configure everything under Admin.

Assets

If any assets are defined (Admin → User Asset Inventory — things like a security code or a piece of equipment), each team member's Edit page shows a checkbox per asset for whether they currently have it. Anyone can update these from Edit; only Admins can change anything else about the account.

Offboarding

Admins see an "Offboard" button next to each other team member (not your own row). After you confirm, their account is deactivated immediately, a new Candidate record is created to track their departure, and offboarding tasks are generated from the "Offboarding" Timeline Template — plus one task per asset they currently have, reminding you to collect or revoke it. Set a "last day" on that new Candidate record afterward to fill in due dates for those tasks.

Active Directory Integration

If Active Directory Integration is configured and enabled (under Admin), user accounts are created and kept in sync automatically from your AD directory as Employee accounts — you shouldn't need to add them by hand. Accounts disabled in AD get deactivated here automatically too. If you manually change a synced account's name, email, role, or active status yourself (including by offboarding them), that specific field is remembered and the next sync won't overwrite it — useful for promoting a synced account to Admin, for example.

These sections are system configuration, intended for whoever technically administers this deployment rather than day-to-day users.

  • Active Directory Integration — connection details for your LDAP/AD server (host, port, encryption, a service account's bind DN and password, the search base and user filter to scope which accounts get synced) and how often the sync runs. Use "Test connection" before relying on it, and "Sync now" to run it immediately instead of waiting for the schedule.
  • Email Settings — the SMTP server this app sends all outbound email through (automated email tasks and task reminders both use this). Standard SMTP AUTH fields: host, port, TLS, and credentials for the sending account.
  • Email Templates — the wording for each of the five automated email task types (Infradapt Onboarding, Rejection, Interview Request – Phone, Interview Request – In Person, Offer), each with its own subject/body and live preview, edited independently of the others. Editing one only affects tasks created afterward; ones already scheduled keep whatever was generated when they were created.
  • Task Reminders — a daily digest email to every user with pending tasks due within the next 2 weeks (including anything already overdue), listing what's assigned to them with a link back to this site. Tasks due further out, or with no due date at all, are left out until they fall inside that window. Configure whether it's on, what time it goes out, and the site's public URL for the link.
  • User Asset Inventory — define the assets you want to track who holds (e.g. "Security code - Brookside Office"). Add or remove asset types here; click one to see everyone who currently has it. Whether a specific person has a specific asset is set from their Edit page under Team, not here.
