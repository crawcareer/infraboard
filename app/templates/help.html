Help

The Summary page (this app's home page) has two panels:

  • My Tasks — every task currently assigned to you that isn't done yet. Each row shows the candidate it's for, the task itself, whether it's a Pre-Hire or Post-Hire task, and its due date. A row is highlighted yellow if it's due today, or red if it's overdue.
  • Candidates by Status — a count of candidates in each stage of the pipeline (Prospect, Interviewing, Offer, Hired, Rejected, Archived), with a link through to the full candidate list.

Adding a candidate

Candidates → Add candidate. Only the name is required; email, phone, position, status, and start date are all optional and can be filled in later. You can also attach a resume right away, or add one afterward from the candidate's own page.

Adding timeline events

Open a candidate and use "+ Add event" under either the Pre-Hire or Post-Hire timeline to add a one-off task by hand. If you'd rather start from a checklist, set the candidate's status to "Hired" (or click "Generate timelines from templates") to fill in both timelines automatically from whichever Timeline Templates exist — due dates get calculated from the candidate's start date. Each task can be assigned to a team member, given a due date, and checked off once it's done.

Adding the Infradapt onboarding email task

From either timeline, click "+ Add Infradapt onboarding email task." Pick the date the email should go out, then click Preview to see the email the system will generate (candidate name, start date, and you as the point of contact for questions). You can edit the subject and body before creating the task — whatever you save is exactly what gets sent, automatically, on that date, to Infradapt's support address.

Timeline Templates are reusable checklists that get copied onto a candidate's Pre-Hire or Post-Hire timeline when they're hired. There are two ways to have them:

  • Default templates — click "Generate default templates" here to create a ready-made "Pre-Hire" and "Post-Hire" checklist covering the usual steps (paperwork, equipment, IT accounts, training, check-ins, and so on). It only creates whichever of the two doesn't already exist, so it's safe to click even if you already have one of them.
  • Custom templates — click "New template" to build your own from scratch, or open an existing one to add, reorder, or remove its events. Each event has a title, an optional description, and a day offset (how many days before or after the start date it's due).

A template's name matters only for the two specifically named "Pre-Hire" and "Post-Hire" — those are what get applied automatically when a candidate is hired. Other templates you create are available from a candidate's page but aren't applied automatically.

Employee vs. Admin

Employee accounts can create and manage candidates, be assigned tasks, and create or edit Timeline Templates. They cannot see the Team or Admin pages. Admin accounts can do everything an Employee can, plus manage team members here and configure everything under Admin.

Active Directory Integration

If Active Directory Integration is configured and enabled (under Admin), user accounts are created and kept in sync automatically from your AD directory as Employee accounts — you shouldn't need to add them by hand. Accounts disabled in AD get deactivated here automatically too. If you manually change a synced account's name, email, role, or active status yourself, that specific field is remembered and the next sync won't overwrite it — useful for promoting a synced account to Admin, for example.

The four sections here are system configuration, intended for whoever technically administers this deployment rather than day-to-day users.

  • Active Directory Integration — connection details for your LDAP/AD server (host, port, encryption, a service account's bind DN and password, the search base and user filter to scope which accounts get synced) and how often the sync runs. Use "Test connection" before relying on it, and "Sync now" to run it immediately instead of waiting for the schedule.
  • Email Settings — the SMTP server this app sends all outbound email through (Infradapt onboarding request emails and task reminders both use this). Standard SMTP AUTH fields: host, port, TLS, and credentials for the sending account.
  • Email Template — the wording of the Infradapt onboarding request email, with a live preview. Editing it only affects tasks created afterward; ones already scheduled keep whatever was generated when they were created.
  • Task Reminders — a daily digest email to every user with pending tasks, listing what's assigned to them with a link back to this site. Configure whether it's on, what time it goes out, and the site's public URL for the link.
